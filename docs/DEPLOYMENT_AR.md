# تشغيل النظام على خادم (تجريبي أو نهائي)

نفس الخطوات تمامًا للخادم التجريبي والخادم النهائي. التثبيت بأمر واحد، ويشمل: قاعدة البيانات، الخادم، الواجهة، النسخ الاحتياطي، وشهادة HTTPS تلقائية عند وجود نطاق (دومين).

## 1. الخادم المطلوب
| | تجريبي (حتى ~20 مستخدمًا) | تشغيل فعلي لشركة واحدة |
|---|---|---|
| المعالج / الذاكرة | 2 vCPU / 4 GB | 4 vCPU / 8 GB |
| التخزين | 40 GB SSD | 80 GB SSD + نسخ احتياطي خارجي |
| النظام | Ubuntu 22.04 أو 24.04 | نفسه |

يصلح أي مزود خوادم VPS، أو حتى **جهاز كمبيوتر في المكتب** للتجربة على الشبكة الداخلية فقط. الأسعار تختلف بين المزودين؛ القرار النهائي (D5) يراعي مكان البيانات وسرعة الوصول من ليبيا.

## 2. التثبيت (مرة واحدة)
```bash
# على الخادم
curl -fsSL https://get.docker.com | sh               # تثبيت Docker
git clone https://github.com/golden-chips/sales.git golden-erp   # المستودع خاص: يلزم رمز وصول للقراءة
cd golden-erp/deploy
./setup.sh                                          # تجريبي عبر عنوان IP:  http://IP-الخادم
# أو مع نطاق وشهادة HTTPS تلقائية (النطاق يجب أن يشير لعنوان الخادم مسبقًا):
DOMAIN=erp.example.ly ./setup.sh
```
* السكربت يولّد كلمات سر عشوائية قوية في `deploy/.env` (لا تُرفع للمستودع أبدًا)، يبني ويشغّل كل شيء، يطبّق ترحيلات قاعدة البيانات، ثم يُنشئ الحسابات الأولى و**يطبع كلمات السر مرة واحدة فقط** — احفظها فورًا.
* الحسابات المُنشأة: مدير المنصة، حساب شركة الرقائق الذهبية (دليل حسابات مقترح بدون أي معاملات)، وشركة **DEMO** للتجربة (`SEED_DEMO=false` لعدم إنشائها في التشغيل الفعلي).
* قاعدة البيانات غير مكشوفة للإنترنت؛ الخادم يتصل بها بدور مقيّد (`golden_app`) فيُفرض عزل الشركات على مستوى قاعدة البيانات.

## 3. الجدار الناري
```bash
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw enable
```

## 4. النسخ الاحتياطي
```bash
./backup.sh                                   # نسخة فورية في deploy/backups (يحتفظ بآخر 14)
crontab -e   →   15 2 * * * /root/golden-erp/deploy/backup.sh   # يوميًا 2:15 صباحًا
```
**انسخ مجلد backups خارج الخادم** (جهاز آخر أو تخزين سحابي). تم اختبار الاستعادة فعليًا. أمر الاستعادة مكتوب داخل `backup.sh`.

## 5. التحديث إلى نسخة أحدث
```bash
./update.sh      # نسخة احتياطية ← سحب التحديث ← إعادة البناء والتشغيل ← ترحيلات قاعدة البيانات تلقائيًا ← مزامنة الأدوار
```

## 6. ربط بقية الأجهزة
* **المتصفح**: عنوان الخادم (أو النطاق). يمكن «تثبيته» كتطبيق من المتصفح.
* **تطبيق الأندرويد**: في إعدادات المستودع على GitHub ضع المتغير `GOLDEN_API_BASE` = عنوان الخادم (يُفضّل HTTPS) ثم أعد تشغيل بناء الـ APK.
* **أجهزة البصمة ZKTeco**: في إعدادات الجهاز (ADMS/Cloud Server) ضع عنوان الخادم والمنفذ 80 (أو 443)، وسجّل الرقم التسلسلي للجهاز في النظام.
* **الموقع الجغرافي في تطبيق المندوب والكاميرا**: تتطلب HTTPS (نطاق) — عبر IP فقط يعمل النظام لكن المتصفح قد يمنع الموقع.

## 7. ما تم اختباره فعليًا
التثبيت الكامل بـ `setup.sh` على Docker، تسجيل الدخول عبر nginx، اتصال الخادم بالدور المقيّد بدون تجاوز للعزل، إعادة التشغيل دون تكرار البيانات، النسخ الاحتياطي **واستعادته** في قاعدة منفصلة، وعرض الواجهة في متصفح. ويُعاد اختبار التثبيت تلقائيًا في GitHub مع كل تحديث.

## حدود
* شهادة HTTPS تلقائية تتطلب نطاقًا يشير للخادم ومنفذَي 80/443 مفتوحين.
* لم يُختبر بعد على خادم حقيقي في ليبيا (السرعة، الاتصال)، ولا تحت حمل عدد كبير من المستخدمين.
* إرسال البريد/واتساب يحتاج مزود خدمة (K36).
