# المناديب والتوزيع — دليل سير العمل والربط بتطبيق المندوب (المرحلة 4)

## نموذج التشغيل (مأخوذ من نظام المناديب الحالي)
| المفهوم | في GOLDEN ERP |
|---|---|
| سيارة المندوب | مخزن من نوع `van` — بضاعة في عهدة المندوب (حساب `inventory_van`) |
| التحميل الصباحي | المندوب يطلب ← **أمين المخزن يرحّل** التحويل (فصل مهام طبيعي). **لا يمكن تحميل تشغيلة منتهية أو موقوفة** |
| الفاتورة الميدانية | تُرحّل فورًا من التطبيق (لا يوجد شخص ثانٍ عند المحل) — انظر «الضوابط البديلة» |
| النقد مع المندوب | **عهدة نقدية** (حساب `rep_cash_custody`): البيع النقدي + التحصيل |
| تسليم العهدة | المندوب يصرّح بالمبلغ ← **أمين الصندوق يعدّ ويؤكد**؛ العجز يُسجل ذمة على المندوب (`employee_advances`)؛ المعدود أكبر من المصرّح يُرفض (إعادة عد) |
| تسوية آخر اليوم | المندوب يعدّ كل أصناف السيارة ← **المشرف يعتمد**؛ العجز بالتكلفة على المندوب، الزيادة إلى `inventory_adjustment`؛ الفرق يُحسب على الرصيد الدفتري **لحظة الاعتماد** |
| العمولة | على **المحصّل فعلًا** (بيع نقدي + سندات قبض)، لا على البيع الآجل؛ نسبة ثابتة أو شرائح؛ يحتسبها المالي ويرحّلها مالي آخر (فصل مهام): مدين `commission_expense` / دائن `commissions_payable` |

## الضوابط البديلة لفصل المهام في الميدان
1. **لا يكتب المندوب أسعارًا**: السعر من قائمة الأسعار أو السعر الخاص للعميل فقط (الحقل مرفوض في الـ API).
2. **سقف خصم لكل مندوب** (`max_discount_pct`).
3. **عملاء مُسندون فقط**: على مسارات المندوب أو في منطقته.
4. **حد الائتمان** يُفحص عند كل فاتورة آجلة.
5. **لا بيع لتشغيلة منتهية/موقوفة/مستدعاة**، ولا تحميلها للسيارة أصلًا.
6. **التسوية اليومية** (مشرف) + **تسليم العهدة** (أمين صندوق) — شخصان غير المندوب.
7. كل عملية في سجل التدقيق، ومرتبطة بالمندوب (`rep_id`).

## المزامنة دون اتصال — العقد
`POST /api/v1/field/sync` — مصفوفة عمليات (حتى 200):
```json
{ "ops": [
  { "clientId": "invoice-6f1c…", "type": "invoice", "clientTime": "2026-11-11T09:12:00Z",
    "payload": { "customerId": "…", "paymentType": "cash|credit", "invoiceDate": "2026-11-11",
                 "lines": [ { "itemId": "…", "uomId": "… (اختياري)", "qty": "2", "discountPct": "3" } ] } },
  { "clientId": "receipt-…", "type": "receipt", "payload": { "customerId": "…", "amount": "50", "paymentDate": "2026-11-11", "salesInvoiceId": "… (اختياري)" } },
  { "clientId": "visit-…",   "type": "visit",   "payload": { "customerId": "…", "outcome": "sale|collection|no_order|closed|refused|other", "visitedAt": "…", "lat": 32.88, "lng": 13.19 } }
] }
```
* كل عملية في **معاملة مستقلة**: فشل واحدة لا يوقف البقية.
* **`clientId` فريد يولّده الجهاز**. إعادة الإرسال تُرجع النتيجة الأصلية مع `"replayed": true` — **لا تكرار أبدًا** (مُختبر: نفس الدفعة مرتين، ونفس العملية مرتين متتاليتين).
* العملية المرفوضة لا تُسجّل، فيمكن إعادة محاولتها بنفس `clientId` بعد معالجة السبب (مثل GPS).
* رقم الفاتورة يصدر من الخادم (`SI-…`) — لا حاجة لحجز كتل أرقام على الجهاز في هذا التصميم.

## ربط تطبيق المندوب الحالي (Expo) — خطة
التطبيق الحالي (`van-sales-app/mobile`) فيه طابور دون اتصال ناضج (`src/lib/offlineQueue.ts`). الربط لا يتطلب إعادة كتابة:
1. محوّل (adapter) يحوّل عمليات الطابور الحالية (`kind: "create"` على `invoices`/`payments`/`visitNotes`) إلى عمليات `/field/sync` بنفس المعرّف `op.id` كـ `clientId`.
2. استبدال قراءة Firestore لمسار اليوم والكتالوج ورصيد السيارة بـ `GET /field/my-day`.
3. تسجيل الدخول: `POST /auth/login` (رمز الشركة + البريد + كلمة المرور) بدل PIN؛ أو إضافة دخول PIN لاحقًا كخيار للمستأجر.
4. فترة تشغيل متوازٍ: التطبيق يكتب للنظامين، ومطابقة يومية للمبيعات والتحصيل قبل إيقاف الكتابة لـ Firestore.
> لم أعدّل مستودع `van-sales-app` في هذه المرحلة؛ واجهة المندوب الجديدة (`/field` في تطبيق الويب، تعمل على الجوال ودون اتصال) جاهزة ومُختبرة كبديل أو كمرجع للمحوّل.

## الإشعارات
الاستدعاء يضيف رسالة واتساب (`product_recall`) لكل عميل متأثر له رقم هاتف في `notification_outbox`. **الإرسال الفعلي غير مفعّل بعد**: يحتاج ربط حساب Meta WhatsApp الحالي للشركة (المرحلة القادمة)، وحتى ذلك تبقى الرسائل «في الانتظار» ظاهرة في شاشة «رسائل العملاء».

## الخصوصية
GPS للزيارات **معطّل افتراضيًا**، وتفعّله الشركة من الإعدادات (`fieldGpsRequired`) بقرارها، ويُسجل فقط عند الزيارة (لا تتبع مستمر).

## غير منفّذ بعد
تتبع السيارة الحي، تخطيط الرحلات وتحسين المسار، الأسطول (صيانة، وقود، رخص)، إثبات التسليم بالتوقيع والصورة، طلبات العملاء عبر رابط/واتساب، مصروفات المندوب الميدانية، أوامر البيع المسبقة للتوصيل.
