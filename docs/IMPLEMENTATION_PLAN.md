## قياس نسبة الإنجاز

## معايير القبول لكل مرحلة (مختصر)

* **1:** لا وصول متبادل بين المستأجرين (اختبارات RLS)، تعليق المستأجر يوقف الدخول فورًا، حدود الباقة مفروضة في الخادم، كل تغيير مُدقق. ✅ مختبر.
* **2:** لا قيد غير متوازن يمكن ترحيله حتى بتجاوز الخدمة، لا تعديل لقيد مرحّل، الإقفال يمنع الترحيل، ميزان المراجعة متوازن دائمًا، كل رقم يُتتبع لمستند. ✅ مختبر للمنفّذ.
* **2b:** دورة بيع كاملة (أمر → تسليم → فاتورة → تحصيل) ودورة شراء (طلب → أمر → استلام → فاتورة مورد → سداد) تنتج قيودًا صحيحة وأرصدة مخزون صحيحة بتكلفة متوسط مرجح؛ اختبارات تكامل لكل دورة.
* **3:** BOM بإصدارات، أمر تشغيل بصرف/استلام/هدر، تكلفة فعلية مقابل معيارية، تتبع دفعة من المورد إلى العميل، استدعاء بتقرير أمامي/خلفي.
* **4:** تطبيق المندوب يعمل مقابل API الجديد دون اتصال مع مزامنة بلا تكرار (Idempotency-Key)، تسوية العهدة.
* **5:** محرك الرواتب الحالي مغطى باختبارات، مسير الرواتب ينشئ قيده، أجهزة البصمة تُرسل إلى API الجديد.

## الخطوة التالية مباشرة (المرحلة 5 — الموارد البشرية والرواتب)

دمج «حضوري»: الموظفون في GOLDEN ERP (المندوب موظف)، استقبال بصمات ZKTeco الحالية (iclock + bridge) إلى API الجديد، نقل محرك الحضور `engine.ts` مع تغطيته باختبارات، مسير الرواتب بقيده المحاسبي، السلف والقروض، وقواعد استقطاع قابلة للتهيئة لكل دولة (بعد اعتماد النسب).

## (تاريخي) المرحلة 4

ربط تطبيق المندوب الحالي (Expo) بالـ API الجديد: السيارات كمخازن `van`، تحميل/تسوية العهدة، فاتورة ميدانية بدون اتصال مع Idempotency-Key، التحصيل بعهدة المندوب، الزيارات والمسارات، العمولات على المحصّل. مع ترحيل بيانات المناديب الحالية بعد الاعتماد.

## (تاريخي) المرحلة 3

وصفات وقوائم مواد بإصدارات، أوامر تشغيل (صرف مواد خام وتعبئة، استلام منتج تام إلى الحجر، هدر ومنتجات ثانوية)، تكلفة فعلية مقابل معيارية، فحوص الجودة ونقاط HACCP، الإفراج عن الدفعات، والاستدعاء — كلها مبنية على محرك المخزون والتشغيلات المنفّذ في 2b.

## (تاريخي) خطة المرحلة 2b

1. جداول: `parties` (عملاء/موردون)، `items` (خام/نصف مصنع/تام/تعبئة) مع وحدات قياس وتحويل، `price_lists`، `stock_moves` + `stock_balances` (تكلفة متوسط مرجح لكل مخزن/دفعة)، `lots` (تاريخ إنتاج/انتهاء).
2. مستندات: أمر بيع، إذن تسليم، فاتورة بيع، سند قبض، مرتجع (إلى الحجر)؛ أمر شراء، إذن استلام، فاتورة مورد، سند صرف.
3. كل مستند يرحّل عبر `postFromSource` مع أدوار الحسابات الموجودة الآن في الدليل.
4. اختبارات تكامل لكل دورة + اختبارات تكلفة المتوسط المرجح.
